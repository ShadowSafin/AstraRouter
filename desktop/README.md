# AstraRouter desktop app (Windows) — one self-contained `.exe`

A real installed Windows application: **one executable** that carries its own
runtime inside it. Opening it starts the embedded PostgreSQL database, the
AstraRouter gateway and the dashboard, then loads the dashboard in a WebView
window. No Docker, no system database, no admin rights, nothing to start by
hand. The Docker deployment is a separate path and is never touched.

```text
desktop/dist/
  AstraRouter.exe     one self-contained app (gateway + node + dashboard embedded)
  install.ps1         per-user installer (installs just the .exe)
  uninstall.ps1       per-user uninstaller
  README.md
```

## Layout

```text
desktop/
  cmd/shell/            the app: WebView window + supervisor + self-extraction
  cmd/icongen/          icon renderer (stdlib only)
  internal/payload/     go:embed tree — build.ps1 stages the runtime here
  pkg/dbembed/          embedded PostgreSQL lifecycle, DSN handoff
  pkg/supervisor/       child processes, readiness, dotenv parsing
  assets/               icon.png + icon.ico (checked in, regenerated by icongen)
  templates/            config.yaml + native.env.template (used on first run)
  build.ps1             stages the payload, emits dist/AstraRouter.exe
  install.ps1           per-user installer (copied into dist/)
  uninstall.ps1         per-user uninstaller (copied into dist/)
```

## How it works

1. `build.ps1` compiles the gateway and the dashboard, downloads a portable
   `node.exe`, stages all of it under `internal/payload/files/`, and compiles
   the shell with that tree embedded (`go:embed`). The output is a single
   `AstraRouter.exe`.
2. `install.ps1` copies that one file to `%LOCALAPPDATA%\AstraRouter`, runs
   `AstraRouter.exe --migrate-only` to extract the runtime and pre-fetch the
   embedded database, then creates Start Menu / Desktop / Startup shortcuts and
   an Add/Remove-Programs entry.
3. On launch the shell extracts the embedded runtime into its data directory
   (first run only), creates `native.env` + `config.yaml` with fresh secrets and
   free loopback ports, starts embedded PostgreSQL, applies migrations
   (idempotent), supervises gateway + dashboard with crash recovery, waits for
   readiness, and loads the dashboard in the WebView window.
4. The gateway binary is used unmodified: it sees `AR_POSTGRES_DSN` (which
   wins over the config file) and behaves exactly like the native path.

Redis, NATS and ClickHouse are not bundled: the gateway degrades gracefully
without them (in-process rate limiting, no async fan-out, no local trace
persistence), which is the same posture as a minimal native install. The
bundled config seeds a `local-ollama` provider slot so `/ready` passes out of
the box; add real provider keys in the dashboard.

## Data directory

The app writes everything user-owned under one directory and never asks the
user to manage it:

```text
%LOCALAPPDATA%\AstraRouter\
  AstraRouter.exe   the app (installed copy)
  bin\              gateway + node, extracted from the .exe on first run
  dashboard\        dashboard server, extracted from the .exe on first run
  data\postgres\    embedded database (binaries, cluster, cache)
  logs\             one file per process + shell-bootstrap.log
  native.env        secrets + ports (owner-only file ACL)
  config.yaml       gateway config (loopback, traces off, ollama slot)
  .payload-version  records which embedded runtime was extracted
```

## Build & test

```powershell
# full single-file build (needs Go, Node 20+, network)
.\build.ps1              # -> desktop/dist/AstraRouter.exe

# unit tests for the desktop module
go test ./...            # from desktop/

# install a test copy without touching the real profile dirs
.\dist\install.ps1 -Target $env:TEMP\ar-dt -NoShortcuts -NoStartup -NoLaunch
.\dist\AstraRouter.exe --smoke --root $env:TEMP\ar-dt
```

`--smoke` starts everything, asserts the dashboard serves its login title,
shuts down cleanly and exits 0/1 — it is the headless end-to-end check used in
place of clicking through the GUI. `--migrate-only` extracts the runtime,
starts the database, applies migrations and stops (what the installer runs).
